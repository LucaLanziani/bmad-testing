# Story Template

Use this template format when generating stories and creating GitHub issues.

## Story Display Format (for review)

```markdown
### Story {Epic}.{Story}: {Story Title}

**As a** {user type},
**I want** {capability/feature},
**So that** {benefit/value}.

**Acceptance Criteria:**

```gherkin
Given {initial context/state}
When {action taken}
Then {expected outcome}
And {additional expectations}
```

**Technical Notes:**
- API: {endpoint and method from Architecture}
- Data: {models/schemas involved}
- Auth: {authentication/authorization requirements}
- Validation: {input validation rules}

**UX Notes:** *(if applicable)*
- Component: {UI component reference}
- Interaction: {behavior pattern}
- States: {loading, error, success states}
- Accessibility: {a11y requirements}

**Prerequisites:** Story {X.Y} *(or "None")*

**Priority:** {High | Medium | Low}

---
```

## GitHub Issue Body Format

When creating the GitHub issue, format the body as:

```markdown
## User Story

**As a** {user type},
**I want** {capability},
**So that** {benefit}.

## Acceptance Criteria

- [ ] Given {context}, when {action}, then {result}
- [ ] Given {context}, when {action}, then {result}
- [ ] {Additional criterion}

## Technical Implementation

### API Endpoint
`{METHOD} {endpoint}`

### Data Model
{Relevant schema or model reference}

### Security
- {Auth requirements}
- {Validation rules}

### Performance
- {Any performance requirements}

## UX Specifications
*(Include if UI-related)*

- **Component:** {Reference}
- **Interactions:** {Patterns}
- **Error Handling:** {States}
- **Responsive:** {Breakpoint behavior}

## Dependencies

- Requires: #{prerequisite_issue} *(if applicable)*
- Blocks: *(filled in later if needed)*

## Definition of Done

- [ ] Code complete and reviewed
- [ ] Tests written and passing
- [ ] Acceptance criteria verified
- [ ] Documentation updated (if needed)

---
*Epic: {Epic Title}*
*Generated by: create-epics-and-stories-github workflow*
```

## Example Story

```markdown
### Story 2.1: User Registration Form

**As a** new user,
**I want** to create an account using my email address,
**So that** I can access the platform's features.

**Acceptance Criteria:**

```gherkin
Given I am on the landing page
When I click the "Sign Up" button
Then the registration modal opens

Given I am on the registration form
When I enter a valid email address
Then the email field shows a green checkmark

Given I have entered valid registration data
When I submit the form
Then my account is created and I receive a verification email
```

**Technical Notes:**
- API: POST /api/v1/auth/register
- Data: Users table with bcrypt password hash
- Auth: None required (public endpoint)
- Validation: RFC 5322 email format, 8+ char password

**UX Notes:**
- Component: RegistrationModal (UX Spec 3.2)
- Interaction: Real-time field validation
- States: Loading spinner on submit, success/error toasts
- Accessibility: Form labels, error announcements

**Prerequisites:** Story 1.5 (API Framework Setup)

**Priority:** High
```
